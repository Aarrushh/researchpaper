The studyThe whole story in plain words

0.1The question

A vision-language model (VLM) can read text in a picture. The pictures it reads were drawn by text-rendering software made for human eyes: fonts, hinting, anti-aliasing, line layout. But a VLM does not look the way you do. It cuts every image into a fixed grid of small squares, the patches, and works from those.

So the study asks three questions:

  1. Does the way text is drawn change how accurately a VLM transcribes it?
  2. If it does, through what mechanism, and which choices matter most?
  3. Is there a rule that holds for every model, or must each model be measured?

Why systems people care. Some systems now feed long text to a model as an image, to spend fewer tokens (visual text compression; Glyph and DeepSeek-OCR). In such a system, rendering decides how much text each vision token can carry before errors creep in.

Worked example

A Qwen2.5-VL-3B page of 448 × 448 pixels always costs 256 vision tokens. On prose at 1% character errors, each of those tokens carried 2.27 times the characters of one ordinary text token (read off the measured sizes, load/readoff_tokens.csv) E P. On random letters and digits, no reader reached even one text token's worth: 0.58 at best.

0.2How a reader sees a page

Follow one page through Qwen2.5-VL-3B, the study's main reader:

  1. Drawn at native size. The page is drawn at exactly 448 × 448 px, the size this reader takes, so its software never resizes it. A check feeds the page to the reader's own processor and confirms that the encoder receives an array of the page's size, as 256 vision tokens (spec rule R07) T.
  2. Cut into patches. The vision encoder cuts the page into 14 × 14 px patches, 32 × 32 = 1,024 of them. Its first layer, the patch embedding (layer 0), turns each patch's pixels into one vector.
  3. Mixed. Transformer layers then share information between patches. In 28 of Qwen's 32 encoder blocks, a patch looks only at patches in the same 112 × 112 px window.
  4. Merged. Each group of 2 × 2 neighbouring patches becomes one vision token: 256 tokens, one per 28 × 28 px token cell.
  5. Read. The decoder, a language model, reads the 256 vision tokens and the prompt, then writes the transcription one text token at a time, always taking its most likely next token (greedy decoding).

Hold on to one point: the grid never moves. Where a letter falls against it decides which pixels end up in the same patch.

0.3Phase and coherence

Phase is where a letter sits against the patch grid: its offset from the patch edge, between 0 and 13 px when patches are 14 px wide. Move a letter 14 px to the right and its phase is back where it started: the next patch sees exactly the pixels the previous one saw. That is why layer 0 gives the same output, shifted, for shifts of whole patches and for no other shift (Figure 0, shift-equivariance) T.

Coherence says whether a page has a phase at all. In ordinary text, letters have different widths, so they land at every phase. Shift the whole line sideways and every letter moves, but the mix of phases stays the same: the page as a whole has no horizontal phase. Only a layout that gives every letter the same phase can show a phase effect. Vertically it is different. The letters of a line share a baseline, so when the line pitch equals the token cell, every line, and so every letter, sits at the same vertical phase (block V, section 0.6).

Worked example

Take 2,500 letters of prose at 16 px. If their phases were random, the coherence R₁ would be about 1/√2,500 = 0.02. Ordinary text measured R₁(14) = 0.022, so its phases are as good as random. The slot layout, one letter per patch-wide slot, measured 0.986: nearly every letter at the same phase (PREREGISTRATION.md §1) T.

That check used 16 px letters. On the study's own pages the slot layout averages 0.58–0.95 and ordinary text 0.03–0.13, by reader and text type (full/coherence_summary.csv) D. The two-slot letters, explained below the figure, pull the slot layout down.

The slot layout has a catch. At 24 px, 12 of the 62 random characters (B D G H M N O Q U W m w) are wider than a 14 px patch. Each takes two slots, centred on the edge between them, and leaves white space beside it. That lowers the random text's coherence to R₁(14) = 0.584 (the 15 October amendment to PREREGISTRATION.md), and it is the key to Study 1.

0.4Scoring: the character error rate

Each page has a reference, the text that was drawn, and a transcription, what the reader wrote. The character error rate (CER) counts the fewest single-character edits that turn the transcription into the reference, per character of the reference:

CER = (S + D + I) / (H + S + D)

S counts substitutions (a wrong character), D deletions (a missing one), I insertions (an extra one) and H hits (correct ones). H + S + D is the length of the reference.

Worked example

Reference abcdefgh, transcription QabXdegh. The reader added Q, wrote X for c and dropped f: S = 1, D = 1, I = 1 and H = 6, so CER = 3 / 8 = 0.375. (This pair is a test case in tests/test_load_check.py.)

For scale, a real number: Qwen-3B read Study 2's ordinary pages of random text at CER 0.0154, about 3 errors on a 201-character page (load/contrasts.csv).

Three rules, fixed before any data (decision D13):

  • Same treatment for both strings. Both are normalised the same way (normalise_text). Case is kept and every character counts, spaces included.
  • Pooled, never averaged. Errors and characters are summed over all the pages of a condition, then divided. One 10-character page with 1 error and one 990-character page with none pool to 0.001; their page rates would average to 0.05.
  • No ceiling. Insertions can push CER above 1, for example when a reader loops.

Reading errors and behaviour. Some errors are not misreading at all: a line skipped inside text read correctly, an unfinished last sentence dropped, a chat preamble such as "Sure, here is the text:", capitals written in lower case. Rules R1–R5 of ANALYSIS_PLAN_3.md §1 split each page's errors into reading errors and behaviour. The primary CER stays the measure; the split is exploratory E and changed no preregistered verdict.

0.6The three studies

Three data sets, 40,788 rows in all, plus the 216 rows of Study 1's size ladder. Each card says what was asked, what was found, and where the numbers live.

Study 1 · Does phase matter, and does one letter per patch help?

prereg-v135,752 rowsQwen-3B, SmolVLM-2.2B, SmolVLM-500Mat 24, 24 and 20 px47, 170 and 89 pages per text type

Asked (H1, in three clauses). (a) When letters share a phase, CER rises and falls periodically with it. (b) The period is the patch or the token cell. (c) At the best phase, the slot layout reads better than ordinary text.

Design. Six blocks of pages: V (ordinary text whose line pitch equals the token cell, shifted vertically through one cell), H (the slot layout, shifted horizontally through one patch), C (ordinary text shifted horizontally: the control, predicted flat), S (quarter-pixel shifts), A (anti-aliasing modes) and Z (sizes 10–24 px, on their own pages).

Found.

  • (a) and (b) supported for all three readers, mostly at the patch period C. Example: Qwen-3B in block H, RMS amplitude 0.0171, p < 0.001.
  • The control C, ordinary text shifted sideways, stayed flat (smallest Holm-adjusted p 0.089) C: it has no horizontal phase. Ordinary letters do vary once their lines sit on the token cell. Block V is significant for all three readers, for Qwen-3B on random text only C.
  • (c) reversed C: the slot layout raised CER on random text, by +0.162, +0.114 and +0.046. On prose, a secondary test, the differences were 0.000, −0.0071 and +0.028.
  • Why it reversed: section 0.7 P.

Study 2 · Does monospace one patch wide fix it, and do the rules travel?

prereg-v24,140 rowsall five readers60 pages per text type (SmolVLM-2.2B 90; SmolVLM-500M prose only)

Asked. Does a monospace font whose advance is exactly one patch (Fira Mono) keep the slot layout's sharp letters without its gaps? And do the results hold on the two new readers?

Conditions. S0, S5, S10: the ordinary sans at 25 px (29 px when P = 16) at three phases. Q0: Study 1's slot layout. M0, M3: monospace, contained (each letter inside one patch). M7 (M8 when P = 16): monospace shifted half a patch, so patch edges cut every letter. S28: the sans at 28 px, matched to the monospace's density.

Found (monospace minus the comparison, so negative means monospace read better):

  • H3, monospace against the slot layout: supported for all four random-text readers, −0.17 to −0.24 inserted spaces per character (H3 counts spaces, not CER), and no worse than ordinary text C.
  • H4, contained against cut: supported for InternVL3-2B (−0.0102) and SmolVLM-2.2B (−0.0225), not for the Qwen pair (0.0000) C.
  • H5, monospace against ordinary text: a gain for InternVL3-2B (−0.0153) and SmolVLM-2.2B (−0.0151), parity for the Qwen pair C.
  • H6, prose no worse than ordinary text by more than 0.01: passes for four readers; SmolVLM-500M fails, with an upper end of +0.0557 C.
  • H7, H3 and H4 both hold on the validation readers: fails, because Qwen-7B misses H4. H3 held on both C.
  • S28: monospace beats the density-matched sans only for InternVL3-2B (−0.0099) D.
  • Re-scoring with rules R1–R5: no verdict changes E.

Stage 0 and Amendment 2 · How does error fall with letter size, and what does a vision token carry?

exploratory896 rows (784, plus 112 in an upper ladder for InternVL3-2B prose)all five readersrandom text and prose16–74 GPU-minutes per reader

Asked. For each reader and kind of text: how does CER fall as letters grow, at what size does it reach 1%, and how many characters does one vision token carry there?

Method. Full pages of text at a ladder of sizes, and a curve CER(s) = 1 / (1 + (s/a)^β) fitted per reader and text type. From the curve: s01, the size at 1% CER; κ01, the characters per vision token at s01; and the token ratio, κ01 ÷ characters per text token.

Found.

  • Readers differ hugely. Read off the measured sizes, κ on prose runs from at most 1.62 (SmolVLM-2.2B) to 11.31 (Qwen-7B) E P. The fits give 1.18 to 9.00, but both ends are weak: SmolVLM-2.2B's s01 lies past its largest size, and Qwen-7B's fit is flagged E.
  • So does the kind of text: read off, Qwen-7B's κ is 11.31 on prose and 0.87 on random text E P.
  • Only the Qwen pair's vision tokens beat text tokens, and only on prose: 2.27 and 2.46 read off (1.78 and 1.96 fitted) E P.
  • Amendment 2 E P. In stage 0, bigger letters also meant fewer characters per page, so the curve mixes size with load. Pulled apart (figure below), load explains most of it: a, β and s01 describe full-page capacity, not acuity.

0.7The story arc

Read the studies as one sequence: this is the paper's spine.

  1. A preregistered prediction reversed. Study 1 predicted that one letter per patch would read better. It read worse: +0.05 to +0.16 CER on random text C.
  2. A mechanism, found afterwards. The encoder does see slot letters better: a probe recovers the letter from Qwen's layer 0 82–88% of the time, against 11–13% for ordinary text. But the decoder treats white gaps as word breaks: it reads a gap as a space half the time at 8.5 px (Qwen, 1.84 million letter pairs), and two-slot letters leave 9–14 px P. Qwen-3B and SmolVLM-2.2B inserted 0.178 and 0.165 spaces per character, 94% and 72% of them beside a two-slot letter E.
  3. The mechanism tested, preregistered. Study 2's monospace one patch wide cut the slot layout's false spaces for all four readers (H3) and beat ordinary text for only two (H5). It failed the transfer test: Qwen-7B missed the containment test H4, so H7 fails C.
  4. A calibration that ranks what matters. Stage 0 measured each reader's curve and its cost in tokens: the reader and the kind of text dwarf every rendering choice E.
  5. A correction the authors found themselves. A last check showed the curve mostly measures page load, and the analysis plan was amended to say so before any writing E P.

0.9What it does not show

  • Any speed-up, encoder compute or energy figure: H2 never ran, and the token ratio ignores the encoder's own pass. Stage 0 did log each page's time on the laptop GPU E: a cost of the method, not a benchmark. The times are latency_s in s3_stage0/pages.csv. The medians by reader and text type are in latency.csv, which leaves out 28 of Qwen-3B's 56 random-text pages as inflated.
  • Tasks other than transcription, such as answering questions or summarising.
  • Readers it did not measure, or models larger than 7B.
  • Scripts other than Latin, and faces other than Source Sans 3 and Fira Mono (one pilot tried Source Code Pro).
  • Real documents. These pages are plain text, black on white, at each reader's native size; real systems resize images and lay out columns, tables and pictures.
  • Other prompts or sampling: one prompt, greedy decoding.
  • Size apart from load: stage 0 moved them together (Amendment 2).

0.10How it was done

Every number passes through the same six steps. When someone asks "how exactly?", this is the map.

  1. 1

    Render

    Draw each page exactly: Source Sans 3 or Fira Mono, unhinted FreeType 2.13.2, black on white, grey edges by coverage in sRGB.

    src/mrr/render.py · grid.py (patch grid, slots, phase) · color.py
    configs/readers.yaml · configs/sweeps/*.yaml
    checks: scripts/02_render_check.py · 08_contract_checks.py → reports/tables/contract/

  2. 2

    Read

    Load each reader, give it the page at native size with the one prompt, and decode greedily up to the token limit.

    src/mrr/readers.py · sweep.py · manifest.py
    scripts/10_run_sweep.py · 11_run_schedule.py
    → results/runs/<run_id>/: results.csv (a row per page and condition), the transcriptions, manifest.json

  3. 3

    Score

    Normalise both strings, align them, count S, D and I, and apply rules R1–R5 for behaviour.

    src/mrr/score.py · behaviour.py · study2.py

  4. 4

    Analyse

    Paired Wilcoxon tests, the bootstrap (over pages; over passages in stage 0), harmonic F-tests with Holm, curve fits and the load check.

    src/mrr/stats.py · acuity.py
    scripts/20_analyze.py → full/ · 22_analyze_study2.py → study2/
    25_fit_stage0.py → s3_stage0/ · 26_rescore_study2.py → study2_rescored/ · 27_load_check.py → load/

  5. 5

    Draw

    Figures straight from the frozen rows or tables, never by hand.

    src/mrr/plotting.py · scripts/03_equivariance.py (Figure 0) · 30_make_figures.py (1, 2, 3, 3a, 4) · 31_stage0_figures.py (5, 6) → reports/figures/

  6. 6

    Freeze

    Hash every run folder (44,989 files) and check that the result tables regenerate byte for byte. The figures were checked once, at analysis-freeze-v1.

    scripts/40_freeze.py · make freeze-check-all (about 35 minutes, CPU only) → results/final/

Instruments, which measure the readers themselves without any transcription: 03_equivariance.py (Figure 0), 04_mtf.py (Figure 3a, the layer-0 modulation transfer), 05_coherence.py (the R₁ table), 08_contract_checks.py (spec conformance) and 09_ladder_choice.py (Study 1's sizes).

Machine and settings. One laptop GPU (RTX 5060, 8 GB) and 32 GB of RAM; weights in bfloat16, with Qwen-7B in 4-bit NF4 to fit. One prompt for every page: "Transcribe all text in the image exactly. Output only the text." At most ⌈1.5 × the reference's length in the reader's own tokens⌉ new tokens. Bootstrap seeds 20261014 (Study 1) and 20261021 (Study 2).

  • The load finding for prose. It holds on random text; prose is mixed.
  • The working title's "designed for vision encoders", unchecked. The strongest effects measured are the decoder's (spaces) and the page's (load), as R10 notes.

0.12Reviewer questions

Questions a careful reviewer is likely to ask, with the answers the data support. Try each before opening it.

1 · "Your preregistered prediction (c) failed. Why should anyone believe the story you told afterwards?"
  • (c) is reported as reversed, under the preregistered measure and test: +0.162, +0.114, +0.046 C.
  • The explanation is labelled post hoc P and has independent support: the decoder's space threshold, measured on 1.84 million letter pairs (50% at 8.5 px, Qwen); the 9–14 px gaps beside two-slot letters; 94% and 72% of the inserted spaces beside a two-slot letter E; a pilot that narrowed the wide letters cut false spaces from 0.170 to 0.0014 per character.
  • Then the mechanism made a prediction, preregistered as Study 2: monospace one patch wide removes the false spaces. H3 held for all four readers, measured in inserted spaces per character C.
2 · "Five small models. Why would any of this generalise?"
  • It is not claimed to: the paper states no rule for a reader it did not measure.
  • The five span three encoder families and two decoder families, and H7 tested generalisation directly. It failed on one of its two parts C: H3 held on both new readers, but Qwen-7B missed H4, as Qwen-3B did. That is evidence that rules must be measured per reader: part of the point.
  • What does carry over is geometry T: native size, no resampling, the blind strip, whole-patch equivariance, all defined by P and the merge.
  • Measuring a new reader is cheap: 16–74 GPU-minutes in stage 0.
3 · "Your calibration confounds letter size with the amount of text on the page."
  • Yes. The authors found it with their own check, froze the check as Amendment 2 and report it E P.
  • Full pages read 1.71–3.23 times worse than half-full pages at about the same size; the curve predicts 1.18–1.28. At a fixed load, for the three readers above their cliff, 25 → 28 px changes CER by ×0.84–0.97, against the curve's ×0.48–0.53. Every one of those intervals includes 1. SmolVLM-2.2B, at its cliff, gives ×0.80 [0.61, 1.05]: consistent with the curve's ×0.75, and with no change.
  • So the paper names the curve for what it measures, full-page capacity, and leaves size at a fixed load to future work.
  • Limits to state: random text only; the load comparisons cross studies (different pages; 8 stage-0 pages per size, 16 for SmolVLM-2.2B).
4 · "Where is the systems contribution?"
  • The token ratio prices visual text compression for a given reader at a target error. At 1% CER on prose, the Qwen pair's vision tokens carry 2.27 and 2.46 times a text token's characters; every other reader is below 1; random text reaches 0.58 at best, all read off E P.
  • A byte-exact renderer with a written specification and contract tests, delivering pages without resampling T.
  • Not claimed: throughput, latency or encoder cost.
5 · "Why transcription and CER, rather than a downstream task?"
  • Transcription isolates reading. Question answering mixes reading with reasoning and with guessing from context; the paper's related work covers the evaluation papers.
  • CER is pooled over pages (D13), so each page counts by its length; the tests are paired by page, with page-bootstrap intervals.
  • Errors that are behaviour rather than misreading are split out in an exploratory re-scoring, which changed no verdict E.

ReferenceGlossary

Plain-word definitions, with this study's numbers where they help. Dotted links elsewhere on the page jump here.


No term matches.

The model

VLM (vision-language model)
A model that takes an image and a prompt and writes text. This study uses five, which it calls readers.
Reader
The project's word for a VLM used to transcribe a page. Development readers (Qwen-3B, SmolVLM-2.2B, SmolVLM-500M) shaped the hypotheses; validation readers (Qwen-7B, InternVL3-2B) joined in Study 2 to test them.
Vision encoder
The part of a VLM that turns pixels into vectors; here a Vision Transformer (ViT, cited as vit).
Patch, P
The encoder's smallest unit: a P × P square of pixels. P = 14 px for four readers, 16 px for SmolVLM-500M.
Patch embedding (layer 0)
The first layer: one linear map from a patch's pixels to a vector. It works like a stride-P convolution, which is why its output repeats exactly every P pixels.
Patch grid
The fixed lattice of patch edges over the page. It never moves; the text moves against it.
Merge
Combining neighbouring patch vectors into one token: 2 × 2 for the Qwen pair, 3 × 3 and 4 × 4 for the SmolVLM pair.
Pixel shuffle
A merge that stacks the vectors of a block of patches into one longer vector (SmolVLM, InternVL3).
Token cell
The square of pixels behind one vision token: P times the merge, so 28, 42 or 64 px.
Vision token
One vector the encoder hands to the decoder. A page costs 256 (the Qwen pair, InternVL3-2B), 81 (SmolVLM-2.2B) or 64 (SmolVLM-500M).
Window attention
Attention limited to a local window. Qwen's encoder uses 112 px windows in 28 of its 32 blocks.
Decoder
The language model inside a VLM: it reads the vision tokens and the prompt, and writes text tokens. Two families here: Qwen2-type and SmolLM2.
Text token
The decoder's unit of text, set by its tokenizer: about 4.5 characters on prose (4.49–4.59) and about 1.4–1.5 on random text (s3_stage0/tokens.csv).
Native size
The page is drawn at exactly the size the reader takes, so its image processor never resizes it (spec R07, "Native frame").
Image processor
The model's own preprocessing code: resizing, normalising, cutting into tiles. At native size it does not resize.
Blind strip
Pixels no patch covers. SmolVLM-2.2B's 27 patches of 14 px cover 378 of its 384 px, so columns and rows 378–383 are never seen (spec R08).
NF4
A 4-bit format for model weights. It let Qwen-7B, 16.6 GB of weights in bfloat16, run on the 8 GB laptop GPU. Only its language model's linear layers are 4-bit; its vision encoder and output layer stay in bfloat16.
bfloat16
The 16-bit number format the other readers ran in.

Drawing text

Glyph
The drawn shape of one character in one font.
Advance
How far the pen moves after a glyph; it sets the letter spacing.
Proportional font
Glyphs have different advances: in Source Sans 3, "m" is wide and "i" is narrow.
Monospace font
Every glyph has the same advance (Fira Mono). Study 2 set that advance to one patch.
Rasterisation
Turning a glyph's outline into pixels; here by FreeType 2.13.2, unhinted.
Hinting
Nudging outlines onto the pixel grid so that text looks sharp to people. It is off here, so the pixels follow the outline exactly.
Anti-aliasing
Grey edge pixels whose darkness follows how much of the pixel the glyph covers. Modes tested: binary (none), coverage_srgb (the default) and coverage_linear.
sRGB and linear light
Two ways to turn coverage into a pixel value: sRGB is the standard screen encoding; linear treats light physically. Linear against sRGB showed no significant difference (every p ≥ 0.20), but the smallest detectable differences were 0.008–0.067 CER by reader: "not detected", not "no effect".

Layouts

Conventional rendering
Ordinary text: a proportional font, with letters wherever their advances put them.
Slot layout
Patch-aware rendering: one glyph per patch-wide slot, centred, so every glyph shares a phase. Study 1's block H; Study 2's Q0.
Two-slot character
A glyph wider than a patch, which takes two slots. At 24 px with P = 14: B D G H M N O Q U W m w, 12 of the 62.
Phase (φ)
Where a glyph sits against the patch grid: its offset modulo P, horizontal (φx) or vertical (φy).
Coherence, Rk(T)
How strongly a page's glyphs share a phase: 1 when they all agree, about 1/√N when they are random. In the 16 px check: ordinary text 0.022, the slot layout 0.986. On the study's pages: 0.03–0.13 and 0.58–0.95, the slot layout lowered by two-slot letters.
Shift-equivariance
Shifting the input shifts the output the same way. Layer 0 is exactly equivariant only for shifts of whole patches (Figure 0).
Contained and cut
Study 2's monospace at phase 0, every glyph inside one patch (M0, M3), or at phase P/2, every glyph split by a patch edge (M7; M8 when P = 16).
Density-matched sans (S28)
The sans at 28 px, matched to the monospace's density. It separates "monospace" from "bigger letters".
Blocks V, H, C, S, A and Z
Study 1's sets of pages: V and H sweep phase, C is the control, S shifts by quarter pixels, A varies anti-aliasing and Z varies size (section 0.6).

Text and task

random62
Random strings of the 62 letters and digits, in five-character words. With no language to guess from, every character must be seen.
Prose
Natural text from three Project Gutenberg books: Persuasion, Frankenstein and The Adventures of Sherlock Holmes, so two novels and a story collection. Tables label it natural.
Transcription task
One prompt for every page: "Transcribe all text in the image exactly. Output only the text."
Greedy decoding
The decoder always takes its most likely next token, so a reading can be repeated exactly.
Token limit
At most ⌈1.5 × the reference's length in the reader's own tokens⌉ new tokens per page.

Scoring

CER (character error rate)
(S + D + I) / (H + S + D): substitutions, deletions and insertions per character of the reference. Case kept, spaces counted.
S, D, I and H
Substitution (a wrong character), deletion (a missing one), insertion (an extra one) and hit (a correct one): the outcomes of aligning a transcription to its reference.
Alignment
The cheapest edit path between two strings, computed here with the jiwer library.
Pooled CER (D13)
Errors and characters summed over pages, then divided; never a mean of page rates.
Reading CER
CER on what the reader actually read, with behaviour removed (ANALYSIS_PLAN_3.md §1.2). Exploratory.
Behaviour
Errors that are not misreading: omissions, runaway insertions, format lines and case normalisation, sorted by rules R1–R5.
Omission
A deleted run of 15 or more characters next to well-read text (at most 3 errors in the 30 characters on each side that exists): a skipped stretch, such as a line. Head if it starts at the first character, tail if it ends at the last, otherwise interior (rule R3).
Runaway insertion
An inserted run of 15 or more characters, anchored the same way: a loop or an invented continuation (rule R3).
Case normalisation
A letter written in the wrong case where its two shapes differ (a/A): the reader saw the letter and changed its case.
Shape-alike letters
Letters whose lower case is the capital made smaller (Source Sans 3: c o s u v x z). A case error on one may be a misreading, so it counts as a reading error.

Statistics

Paired design
Every condition reads the same pages, so differences are taken page by page and each page's own difficulty cancels out.
Wilcoxon signed-rank test
A test on paired differences that uses their ranks, so a few extreme pages cannot dominate it.
Median difference
The middle of the page-by-page differences. Negative means the treatment lowered CER.
Bootstrap
Redraw the pages with replacement 2,000 times and recompute; the middle 95% of the results is the interval. Stage 0 redraws passages instead, keeping each passage's pages at every size together (2,000 times for the fits, 500 for the leave-one-size-out bands).
95% interval
The bootstrap range for an effect. A difference whose interval excludes 0, or a ratio whose interval excludes 1, is distinguishable from no effect.
Harmonic F-test
Fits sines and cosines of a given period to CER against phase, and tests whether they explain more than noise.
RMS amplitude
The size of the fitted periodic part of CER, in CER units. 0.01 was fixed in advance as the smallest effect worth reporting.
Holm correction
A step-down rule that keeps the chance of any false positive in a family of tests at 5%.
Detectable amplitude
The smallest effect the data had 80% power to find, reported whenever a test is not significant.
Non-inferiority margin δ
H6 allowed monospace prose to be at most 0.01 worse than the sans, judged by the upper end of its interval.

Process

Preregistration
Hypotheses, tests and thresholds written down, committed and tagged before any data are read (prereg-v1, prereg-v2).
Confirmatory, exploratory, post hoc
The status of a result: the marks C, D, E, P and T of section 0.5.
Amendment
A dated change to an analysis plan, with its reason. ANALYSIS_PLAN_3.md has two.
Deviation
Something a preregistration promised that the study did not do: here, H2.
Freeze and tag
Data and tables hashed at a commit, and the commit named (data-freeze-v2, analysis-freeze-v2). A changed table needs a new tag.
D-numbers
Decisions in docs/05_decisions.md, such as D13 (pooled CER) and D22 (who writes what).
R-numbers
Three different series: spec rules R01–R11 (spec/RENDERING_SPEC.md; R01–R06 say how pixels are drawn, R07–R11 come from the measurements), scoring rules R1–R5 (ANALYSIS_PLAN_3.md §1) and research notes R5–R10. The context says which is meant.

Calibration

Calibration curve
CER(s) = 1 / (1 + (s/a)^β), fitted per reader and text type in stage 0.
a and β
a is the size at which the fitted CER is 0.5; β says how steeply the curve falls.
s01
The size at which the fitted curve reaches 1% CER. Where the table flags s01_disagrees, the read-off size is the better guide.
κ01
Characters per vision token on a full page at s01. Read off, it is taken at the read-off s01 instead, or bounded at the largest size measured.
Token ratio
κ01 ÷ the reader's characters per text token. Above 1, a vision token carries more text than a text token. It equals text tokens per vision token: a compression ratio, at 1% CER.
Read-off and fitted
A value taken from the measured sizes, or from the fitted curve. Amendment 2 reports both. Of stage 0's ten fits, only Qwen-3B's on prose is clean: four are flagged, and five put s01 past the largest size measured.
Leave-one-size-out
A check of the fit: drop one size, refit, and compare the curve with the dropped cell.
Load
Characters per page. In stage 0, bigger letters meant fewer characters per page, so size and load moved together.
Full-page capacity
What the stage-0 curve measures (Amendment 2): the error on a full page at each size, not the reader's acuity.
Cliff
The steep part of a reader's size curve, around a. Below it, letters are too small to read; well above it, size changes little at a fixed load, and page load dominates (Amendment 2). On random text, Study 2's 25 px lies above the cliff for the Qwen pair (25/a = 1.90 and 2.06) and at it for SmolVLM-2.2B (0.98). InternVL3-2B, at 1.28, is on the edge: Amendment 2 counts it above the cliff, while ANALYSIS_PLAN_3.md §3.3 calls 1.0 to 1.3 "near the cliff".
Visual text compression
Feeding text to a model as an image to spend fewer tokens (Glyph, DeepSeek-OCR).
Compression ratio
In visual text compression papers: the text tokens a passage would cost, divided by the vision tokens of its image. DeepSeek-OCR reports its OCR precision against it. The token ratio is the same kind of quantity, measured per reader at 1% CER.
